## Что проверяется

### Unit-тесты бэкенда (`backend/tests/test_unit.py`)
- правила времени брони: окончание позже начала, нельзя в прошлом, кратность 30 минутам, максимум 4 часа, рабочие часы 08–22, бронь в пределах одного дня, граничный случай «ровно до 22:00»;
- начальный статус брони по роли (гость → «ожидает», сотрудник/админ → «подтверждена»);
- матрица переходов статусов (8 случаев: владелец/чужой/админ);
- проверка загружаемых файлов: тип, размер, пустой файл, подделка содержимого;
- хэширование паролей, JWT, хэш токенов;
- валидация схем: сложность пароля, обязательный часовой пояс, порядок времени.

### Интеграционные тесты API (`backend/tests/test_api.py`)
- полный цикл: регистрация → вход → refresh (старый токен перестаёт работать) → выход;
- дубликат email → 409; неверный пароль → 401; формат ошибки валидации с полями;
- восстановление пароля: ссылка из лога, одноразовость;
- блокировка пользователя → вход запрещён;
- RBAC: не-админ не может создать зал, открыть админку и дашборд (403), аноним — 401;
- доступ к чужой брони по ID → 404;
- пересечение броней → 409, бронь «встык» — разрешена; отменённый слот освобождается;
- заявка гостя → подтверждение админом; гость не может подтвердить сам;
- превышение вместимости → 422;
- публичный календарь не раскрывает темы чужих броней;
- поиск, фильтры, сортировка и пагинация залов; поиск пользователей;
- загрузка фото и отказ для неподходящего файла;
- экспорт в Excel, журнал аудита, дашборд;
- редактирование/скрытие/удаление зала, смена профиля и пароля, история действий.

### Фронтенд (`frontend/src/test`)
- расчёт слотов дня (28 ячеек, отметка занятых/прошедших), проверка выбранного интервала;
- склонение «человек/человека», правила пароля, проверка файла;
- `DayTimeline`: занятые слоты заблокированы, клик по свободному, выделение интервала;
- `ConfirmDialog`: подтверждение действия;
- `LoginPage`: ошибки валидации пустой формы, отправка данных;
- `RoomCard`: отображение данных зала и ссылки.

### E2E (`frontend/e2e/booking.spec.ts`)
1. Сотрудник входит → выбирает зал и свободное время → бронирует → видит бронь в «Мои брони» → отменяет с подтверждением.
2. Гость оставляет заявку → администратор подтверждает её на странице «Заявки».

## Найденные и исправленные дефекты

| № | Дефект | Как найден | Исправление |
|---|---|---|---|
| 1 | Обработчик ошибок отдавал 500 вместо 401/409/422: перепутан порядок аргументов `JSONResponse` | интеграционные тесты | аргументы переданы по именам |
| 2 | Ссылка на сброс пароля не попадала в лог: Alembic при запуске отключал логгеры приложения | интеграционный тест восстановления пароля | `fileConfig(..., disable_existing_loggers=False)` |
| 3 | Пользователя «выкидывало» после перезагрузки страницы: два одновременных запроса `/auth/refresh` с одним одноразовым токеном, второй получал 401 | ручная проверка в браузере (ошибка 500/401 в консоли) | параллельные обновления токена объединяются в один запрос |
| 4 | Ошибка импорта: метод `list` в классе перекрывал встроенный тип в аннотациях | запуск сидера | `from __future__ import annotations` |
| 5 | Тест регистрации дубликата падал с 422 вместо 409 — имя из одной буквы не проходило валидацию | интеграционный тест | исправлены тестовые данные |
| 6 | Хостинги выдают адрес БД в формате `postgres://`, SQLAlchemy его не принимает | проверка конфигурации деплоя | адрес автоматически приводится к `postgresql+psycopg://` |
